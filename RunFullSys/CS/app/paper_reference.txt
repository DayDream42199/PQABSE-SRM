Abstract—Mobile cloud systems increasingly rely on searchable
encryption to enable secure data outsourcing with efficient
retrieval. However, supporting multi-keyword search in postquantum (PQ) settings remains highly challenging due to the
computational complexity of lattice-based cryptography and the
resource constraints of mobile devices. Existing solutions either
rely on classical cryptographic assumptions vulnerable to quantum attacks, or incur prohibitive overhead when directly adopting PQ primitives. Moreover, they often lack efficient batch query
processing, adaptive search optimization, and scalable revocation
mechanisms. In this paper, we propose PQABSE-SRM, a postquantum attribute-based searchable encryption framework with
secure revocation tailored for mobile cloud environments. The
proposed framework introduces a lightweight client paradigm in
which mobile data owners perform only symmetric encryption
and hashing, while computationally intensive lattice-based operations are securely offloaded to edge servers equipped with
trusted execution environments (TEEs). To support efficient
multi-keyword search, we design a batch trapdoor construction
combined with an adaptive bitmap-based pruning strategy, significantly reducing communication and computation overhead. Furthermore, we develop a search-coupled, epoch-driven revocation
mechanism that performs candidate-selective, just-in-time reencryption, eliminating the need for costly system-wide updates
while ensuring revocation soundness and forward security. The
framework also incorporates zero-knowledge authentication and
blockchain-anchored state management to provide verifiable and
consistent access control. Security analysis demonstrates that
PQABSE-SRM achieves IND-CPA confidentiality, adaptive INDCKA search privacy, forward privacy, and revocation soundness
under standard lattice assumptions. Experimental evaluation
shows that the proposed scheme significantly reduces client-side
overhead and achieves efficient sub-linear search performance
compared to existing approaches.

I. I NTRODUCTION
The rapid adoption of mobile cloud computing has fundamentally transformed how sensitive data is generated, stored,
and accessed across distributed environments. In domains such
as healthcare, finance, and smart infrastructure, mobile devices
continuously produce large volumes of data that must be
securely outsourced while remaining searchable for timely
decision-making. Searchable Encryption (SE) has emerged

as a key cryptographic primitive to enable keyword-based
retrieval over encrypted data [21], [24]. However, designing
efficient and secure multi-keyword search in post-quantum
mobile cloud environments remains highly non-trivial.
First, most existing SE schemes rely on classical cryptographic assumptions such as discrete logarithms or bilinear
pairings, which are vulnerable to quantum attacks [11], [12].
Transitioning to post-quantum (PQ) constructions based on
lattice assumptions (e.g., LWE/MLWE) introduces significant
computational overhead due to high-dimensional matrix operations and noise sampling [2], [4], [15]. This makes direct
deployment on resource-constrained mobile devices impractical [17], [28].
Second, supporting multi-keyword search in PQ settings
is inherently expensive [20]. Unlike single-keyword search,
multi-keyword queries require either repeated trapdoor generation or complex query structures, leading to increased communication cost and server-side computation [25]. Existing PQSE schemes often lack efficient mechanisms for batch query
processing and scalable candidate filtering.
Third, revocation and dynamic access control remain major
challenges [23], [29]. Traditional revocation approaches either
require re-encryption of all ciphertexts or rely on inefficient
key update mechanisms, which are unsuitable for large-scale
mobile cloud systems [30].Furthermore, many designs fail
to tightly integrate revocation with the searchable encryption
process, resulting in stale access rights or inconsistent system
states [16].
Finally, existing systems often overlook practical deployment constraints. In particular, there is a fundamental mismatch between the heavy computational requirements of PQ
cryptography and the limited resources of mobile devices.
Simply porting lattice-based constructions to mobile environments leads to unacceptable latency and energy consumption
[17].
To address these challenges, we propose PQABSE-SRM, a
Post-Quantum Attribute-Based Searchable Encryption framework with Secure Revocation for Mobile cloud systems. The
key idea is to decouple lightweight client operations from
heavy cryptographic computation by leveraging trusted edge

servers equipped with Trusted Execution Environments (TEEs)
[27], while simultaneously introducing adaptive and leakageaware search mechanisms.
In PQABSE-SRM, mobile data owners perform only
lightweight symmetric encryption and hashing, while computationally intensive lattice-based operations (e.g., ABSE
encapsulation and index embedding) are securely offloaded
to edge/TEE nodes. To enable efficient multi-keyword search,

an adaptive bitmap-based pruning strategy [14], significantly

Furthermore, we design a search-coupled, epoch-driven revocation mechanism that performs candidate-selective, just-intime re-encryption, eliminating the need for costly systemwide updates. The system also incorporates zero-knowledge

B. Revocation and Mobile Efficiency
User revocation remains a primary bottleneck in AttributeBased Encryption (ABE). Traditional proxy re-encryption
(PRE) models provided the foundation for delegating ciphertext updates to a cloud provider [9], but these often
require batch re-processing that drains mobile resources. In
mobile cloud contexts, energy consumption is a critical metric;
research shows that upcoming NIST standards place significant
strain on mobile batteries during key generation and encapsulation [17], [28]. To counter this, ”IoT-friendly” schemes
utilize pre-computation and outsourcing to shift the heavy
lifting from the device to the edge or cloud [1], [13]. Recent
implementations have integrated revocation features directly
into the lattice structure [16]. For instance, Wang et al. [29],
[30] developed revocable IBEET and ABE schemes tailored
for 6G-enabled IIoT and mobile cloud environments, focusing
on hidden policies and epoch-based updates. Forward security
has also been prioritized, ensuring that even if a secret key
is compromised, previous search queries remain secure [23].
Efficiency is further enhanced in edge-driven systems, where
search operations are optimized for transportation and mobile
data sharing [27].

C. Privacy-Preserving Authentication
To manage user identities without a single point of failure,
decentralized ledgers have been integrated into the cryptographic pipeline. Blockchain-based systems provide an immutable log for identity-based searchable signcryption, particularly in sensitive domains like medical data sharing [3].
These frameworks often utilize Efficient Sparse Merkle Trees
to track registration and revocation states with minimal storage
overhead [6]. To maintain user privacy, anonymous attestation
and Fiat-Shamir with aborts are employed to generate zeroknowledge proofs (ZKPs), ensuring that a user’s global identifier (GID) remains hidden during the search process while
maintaining mathematical non-repudiation [7], [8].
D. High-Dimensional Search and Bitmap Optimization
The performance of multi-keyword search is often limited
by the high dimensionality of encrypted indexes [19]. Early

bitmap compression techniques, such as Word Aligned Hybrid

with scalable on-demand result processing to handle multiauthority environments [22], [25]. Finally, the shift toward
online/offline encryption ensures that the most computationally
expensive components of the search are prepared before the
mobile user even initiates a query [10].
III. O UR P ROPOSED S YSTEM
A. System Model
We consider a post-quantum, multi-keyword searchable
encryption framework for mobile cloud systems, consisting
of the following entities:
1) Mobile Data Owner (MDO): The MDO extracts keywords from plaintext data and defines an LSSS-based
access policy. It encrypts data using a lightweight symmetric cipher and protects both the encryption key and
keywords using a lattice-based ABSE scheme. A secure
searchable index is generated to support multi-keyword
queries, and the ciphertext bundle is uploaded to the
Cloud Server.
2) Mobile Data User (MDU): The MDU holds attributebased secret keys. To perform a multi-keyword query, it
generates trapdoors for queried keywords and produces
a zero-knowledge proof of valid (non-revoked) identity.
The request is signed using a post-quantum signature
and sent to the Cloud Server. Upon receiving results, the
MDU verifies access policy and decrypts the data.
3) Edge/TEE Node: A trusted edge server equipped with
Trusted Execution Environments (TEEs) assists in performing computationally intensive lattice-based operations, such as key encapsulation and index construction,
on behalf of mobile devices.
4) Cloud Server (CS): The CS stores ciphertexts and processes search queries. It verifies authentication and proof
validity, then performs efficient multi-keyword search
using a Search Optimization Layer (SOL), which applies
inverted indexing and bitmap-based pruning to reduce the
search space before lattice-based verification.
5) Trusted Authority (TA): The TA initializes system
parameters and issues attribute-based keys. It manages
revocation by updating system epochs and distributing reencryption keys to the Cloud Server and update tokens to
valid users, enabling efficient revocation without global
ciphertext updates.
6) Identity Authority (IA): The IA maintains registration
and revocation states using Merkle trees. It provides users
with authentication proofs and updates the system state
upon registration or revocation.

7) Blockchain and Smart Contracts: The blockchain
stores global system states, including registration and
revocation roots. Smart contracts verify updates and ensure consistent, tamper-proof state transitions, allowing
decentralized verification of user legitimacy.

B. Threat Model
We consider a standard adversarial model in mobile cloud
searchable encryption, consisting of the following entities:
1) External Adversary: An external attacker may eavesdrop, replay, or modify communications, and may possess
quantum computational capabilities to break classical
cryptographic schemes. The adversary may also attempt
keyword guessing or trapdoor inference attacks.
2) Honest-but-Curious Cloud Server: The Cloud Server
follows the protocol correctly but attempts to infer sensitive information from stored ciphertexts, searchable indexes, and query patterns. In particular, it may try to learn
keyword information, access patterns, or relationships
among queried data.
3) Revoked or Unauthorized Users: A revoked user may
attempt to access updated ciphertexts using previously issued keys, while unauthorized users may attempt attribute
collusion or generate forged trapdoors to bypass access
control.
Security Objectives. To address the above threats, the proposed framework ensures:
Post-Quantum Data Confidentiality: Data and keyword
security are protected under the hardness of RLWE-based
constructions.
• Fine-Grained Access Control: LSSS-based policies prevent attribute collusion and enforce correct authorization.
• Multi-Keyword Search Privacy: Trapdoors are randomized and unlinkable, preventing the Cloud Server from
recovering queried keywords.
• Revocation Soundness: Epoch-based key update mechanisms ensure that revoked users cannot access newly
updated ciphertexts.
• Authentication and Replay Protection: Blockchainanchored verification and timestamp validation prevent
impersonation and replay attacks.
• Controlled Leakage: The system may reveal limited
access patterns due to search optimization; however,
keyword contents and plaintext data remain hidden.

F. Integrity and Authenticity
Theorem 5 (Integrity and Authenticity). The proposed framework guarantees the authenticity and integrity of both (i) usergenerated search requests and (ii) global system states maintained during registration, revocation, and epoch transition.
Specifically, except with negligible probability in the security
parameter λ, no probabilistic polynomial-time adversary can
forge a valid request accepted by the Cloud Server or modify
the authenticated system state without detection.
Proof. We prove the theorem by considering the two protected
objects in the system: search requests and global state transitions.
1) Authenticity and integrity of search requests. A valid
search request submitted by an MDU contains, at minimum,
the batch trapdoor TQ , the zero-knowledge proof πGID , the
current version tag Vtag , a timestamp T S, and a signature
σ ← Dilithium.Sign(SKtemp , TQ ∥ πGID ∥ Vtag ∥ T S).
Upon receiving the request, the Cloud Server verifies σ
using the corresponding public key P Ktemp . Therefore, for
an adversary to submit a forged request that is accepted by
the server, one of the following must occur:
1) the adversary forges a valid CRYSTALS-Dilithium signature on a new message not previously signed;
2) the adversary modifies one or more request fields (e.g.,
TQ , πGID , Vtag , or T S) while preserving signature
validity;
3) the adversary replays an old signed request and still
passes freshness and epoch-consistency verification.
Case (1) contradicts the EUF-CMA security of CRYSTALSDilithium. Case (2) is also impossible under EUF-CMA security because the signature binds the entire request tuple; any
modification changes the signed message and causes verification failure. Case (3) is prevented by the timestamp and version
checks performed by the Cloud Server. A replayed request
with stale T S fails freshness verification, while a request
bound to an obsolete epoch fails the version-consistency test
against the current blockchain state.

Hence, except with negligible probability, an adversary
cannot forge or tamper with a valid search request.
2) Integrity and authenticity of global system state. The
global system state consists of authenticated values such as
the registration root Rootreg , revocation root Rootrev , and the
associated epoch or version tag Vtag . These values are updated
only through authorized transactions issued by the Identity
Authority (IA) or Trusted Authority (TA), and each update is

1) the adversary forges a valid Dilithium signature on a
fraudulent state update;
2) the adversary modifies an already signed root value while
preserving verification validity;
3) the adversary alters or removes an already committed
blockchain record.
The first two events again contradict the EUF-CMA security
of CRYSTALS-Dilithium, since every valid state transition is
explicitly signed by an authorized entity and bound to the
exact state value being updated. The third event contradicts the
immutability and append-only consistency of the blockchain

by the smart contract, it becomes publicly verifiable and
computationally infeasible to modify without detection.
Therefore, the integrity of Rootreg , Rootrev , and the associated epoch state is preserved.

• violating the integrity/immutability guarantees of the
blockchain.
Under these assumptions, both events occur only with
negligible probability in λ. Hence, the framework guarantees
authenticity and integrity of queries and system state.
